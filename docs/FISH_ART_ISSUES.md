# Fish Art Issues Log

Tracking known problems with the per-species collection illustrations
(`ios/Currents/Resources/Assets.xcassets/Fish/fish_<id>.imageset`) and how each
was resolved. Art is generated by `scripts/generate_fish_art.py` (Gemini image
edit) via the **Generate Fish Illustrations** workflow (`fish-art.yml`).

Status legend: ✅ fixed · ♻️ queued for regeneration · 🔎 needs review

## Root causes

1. **White ellipse / disc background** — the model returns the fish on a solid
   white (or tinted) *sticker disc* whose corners are transparent but the disc
   itself is opaque. The border-connected flood keyer can't reach it (the true
   border is already transparent), so the disc survives. Fix = regenerate; the
   prompt now forbids any circle/oval/badge/sticker shape and the keyer has a
   white-body safeguard.
2. **Reference-photo only / no art** — the imageset still holds the source
   `.jpg` photo, never replaced by a generated `.png`. These were in the
   quota-blocked tail of the last run. Fix = regenerate.
3. **Key damage (eaten face/tail/body)** — the fish's own dark or coloured
   region was connected to the image border through a gap in the anti-aliased
   outline, so the background flood ran *into* the fish. The 2026-07-05 polish
   sweep worsened these; the clean pre-sweep renders were restored from commit
   `af2aaa3`. Fix = revert (no regeneration needed).
